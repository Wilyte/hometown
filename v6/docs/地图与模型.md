# 地图与模型：自己做地图、改个别模型

## 数据流

```
kit-campground-lake-ad32b0.glb        （整张场景，19.87 MB，174 个摆放件）
        │  tools/split_parts.gd       （拆件器，一条命令）
        ▼
assets/parts/<变体>.tscn              174 个 part 场景（自包含：网格内嵌）
data/maps/campground.json             174 条摆放记录
        │  scripts/map_world.gd       （读写 + 拼装，观看器与编辑器共用）
        ▼
scripts/main.gd      观看器（--shot 出图）       scripts/editor.gd   编辑器（拖动/保存）
```

拆件器按「名字 + 几何签名」分组：同名但几何不同的实例（松树丛、芦苇、码头这类随机
变体）会拆成 `<name>.v2`、`<name>.v3`…… 所以是 **62 种 / 174 个变体**，而不是 62 件复用的模型。
这不是偷懒：这套 kit 的场景 GLB 里每个摆放件的网格都是独立烘焙的（顶点已经是世界坐标），
没有共用资产；要真正复用，得用 polyfork 的 kit `.zip`（62 件独立 GLB）+ 运行时随机化。

## 地图 JSON

```json
{
  "version": 1, "name": "campground", "grid": 4.0,
  "items": [
    { "part": "dome-tent",      "pos": [1.8, 0.0, 9.6],  "rot_deg": [0, 0, 0], "scale": [1,1,1] },
    { "part": "string-light-run","pos": [-8.4, 0.0, 5.5], "rot_deg": [0, -90, 0], "scale": [1,1,1] }
  ]
}
```

- `pos` = 这件模型的「脚底中心」世界坐标；`rot_deg` = 欧拉角（编辑器只改 Y）；
- `grid` 是吸附网格（这套资产按 4 m 设计，可走面统一在 y=0）；
- 手改 JSON 也能用：改完直接跑观看器就是新图。

## 编辑器（最小可用版）

```powershell
pwsh v6/tools/edit.ps1                     # 打开/新建 res://data/maps/campground_edit.json
pwsh v6/tools/edit.ps1 -Map my_map.json    # 另一张图
```

| 操作 | 键 |
|---|---|
| 环绕 / 平移 / 缩放 | 左键拖空白 / 右键拖 / 滚轮（朝光标放大，0.6~450 m） |
| 手机上 | **单指拖 = 环绕**、**双指捏合 = 缩放**（以两指中点为中心）、**双指一起拖 = 平移** |
| 选中 / 移动 | 左键点物体 / 左键拖（4 m 吸附） |
| 上下移动 | Shift + 左键拖（0.25 m 吸附） |
| 旋转 | Q / E ±15°，[ / ] ±1° |
| 缩放 | - / + ±10% |
| 放置 | 点左侧 part 列表 → 点地面；顶部一行选变体 |
| 复制 / 删除 / 撤销 / 保存 | Ctrl+D / Del / Ctrl+Z / Ctrl+S |
| 其它 | G 吸附开关 · F 取景选中 · F5 重烘接触阴影 · Esc 取消 |

存盘就是写回打开时那张 `map.json`；编辑器里改了但没存会显示「●未保存」。

无鼠标验收（会真的放一件、存盘、重读、比对坐标）：

```powershell
godot --path v6 --resolution 1400x900 res://scenes/editor.tscn -- --edit-selftest
# EDIT-SELFTEST part=dome-tent items 174→175 save_err=0 reload=1 moved=0.000
# EDIT-SELFTEST PASS
```

## 改个别模型

三种粒度，都不用动 GLB、不用重跑拆件器：

1. **整体缩放/转向某一件**：把 `parts/<变体>.tscn` 复制到 `parts_over/` 同名，在根节点写
   `transform = Transform3D(...)`。加载时是「摆放变换 × part 根变换」，所以根上的缩放/朝向会保留。
2. **换掉某一件的网格**：在 `parts_over/` 放同名 `.glb`（导出时保持顶点色 `COLOR_0`、
   平面着色、脚底在 y=0），加载优先用 `.glb`。
3. **改材质/配色**：直接在 `.tscn` 里改 `StandardMaterial3D` 的
   `albedo_color` / `vertex_color_use_as_albedo` / `roughness`；同一变体的所有实例共用这一份。

验证覆盖是否生效：

```powershell
python v6/tools/override_demo.py dome-tent 3.0   # 把一个帐篷放大 3 倍写进 parts_over
pwsh v6/tools/shot.ps1 -Out .run/v6-shots/kit_override.png
# 与 shots/kit.png 的差集必须只落在那个帐篷上
```

实测：放大 3 倍 → 影响 5,815 像素、差值集中在一个帐篷；删掉覆盖文件后重新出图与基线
差 `mean 0.0026/255`（等于浮点误差）。

## 重新拆件

改动 GLB 之后要重来：

```powershell
godot --headless --path v6 -s res://tools/split_parts.gd
# SPLIT base_parts=62 variants=174 items=174 meshes=536 tris=162743
godot --headless --path v6 -s res://tools/verify_map.gd
# VERIFY items=174 mismatched=0     ← 逐件比对包围盒，必须为 0
```

`assets/parts/` 是生成物（已 gitignore，17 MB），`parts_over/` 与 `data/maps/*.json` 是人工资产。

## 缩放

- 范围：`cam.min_distance 0.6` ~ `cam.max_distance 450`（米，`data/look.json` 可改）。
  页面原版是 OrbitControls 的 0.35d~2.5d，即 39~279 m，贴着看不了细节。
- 步进：滚轮每格 ×0.85，Shift ×0.97（微调），Ctrl ×0.60（快速）。
- **朝光标放大**：拉近时取景中心会往光标底下那个点挪，所以能一路钻进想看的角落，
  而不是只会往场景中心钻。
- 相机 near 跟着距离按比例收（默认取景距离处仍等于页面的 `radius*0.012`），贴到 1.2 m
  也不裁切，且默认视角与页面保持逐像素一致。
- 出近景证据图：`godot --path v6 -- --shot out.png --cam-dist=4`（也可 `--cam-pitch=-30`）；
  范围自检：`-- --zoomtest`（一路滚到底/推到头 + 朝角落放大后中心是否移动）。

## 拖动不会钻到地面以下

三道闸一起上，缺一都会「透底」：

1. **地形高度图**：启动时把岛体网格按 0.5 m 栅格化（逐三角形重心坐标求高度，
   `196×196`、22,540 个三角形、76 ms），得到一个真实的地面高度场；
2. **相机兜底**：每次更新相机，先查它脚下（XZ）的地面高度，低于「地面 + 1.5 m」就直接抬上去
   —— 坡上、山体边缘、贴着地面都不会钻进去；
3. **俯角硬下限 8°**：`cam.min_pitch_deg`。只按高度兜底还不够：远看时相机在 y≈1.5，
   一旦允许平视（0°），看到的就是岛体侧面/底面 —— 这就是之前「又穿底」的原因。

```powershell
godot --path v6 -- --orbitest
# ORBITEST yaw=0° pitch=8.00° cam_y=16.31 脚下地面=0.00 余量=+14.81
# …
# ORBITEST worst clearance=+0.000 m @yaw=60°     ← 贴山包时刚好被顶到地面+余量
# ORBITEST PASS
```

调参：`cam.floor_margin`（默认 1.5 m）、`cam.min_pitch_deg`（默认 8°）、`cam.floor_y`（默认 0，
岛外/水面的地板高度）。

**已知没做**：相机只避地形，不避树冠和建筑——贴到很近再压角，仍可能钻进一棵树里。
要彻底解决得给道具做碰撞体 + 用 SpringArm3D 沿视线收距，这一轮没上。

## 人物会动

地图里 4 个角色（`park-ranger`、`kid-with-a-flashlight`、`backpacker`、`lake-angler`）
共用同一副 31 根骨的 Mixamo 骨架，但 GLB 里**没有任何动画片段**，所以动作是程序化的：

- **走动**：在自己出生点 6 m 内随机游走，到点停 1~3 s 再走；转身朝行进方向；
- **步态**：`LeftUpLeg / RightUpLeg` 反相摆、后摆腿屈膝、脚踝压、手臂反相摆、脊柱轻微扭转；
- **待机**：呼吸 + 慢慢看来看去；`lake-angler`（钓鱼的）和跪在帐篷边的 `backpacker` 只待机。

参数在 `data/look.json` 的 `actors`：

```json
"actors": { "enabled": true, "speed": 1.15, "wander_radius": 6.0,
            "per_part": { "park-ranger": {"mode":"walk"}, "lake-angler": {"mode":"idle"} } }
```

开关：`--no-actors`（出与页面逐像素比对的静帧时用）、`--sim-t=秒`（出图前先把人物推进若干秒，
取证可复现，随机种子固定）。

注意：骨骼姿态是叠在「导入时的姿态」上的（`q_local = base_local · (base_global⁻¹ · R · base_global)`），
因为这套 kit 的 T-pose 是 bind 姿势、而角色实际站姿在节点姿态里。幅度刻意保守（大腿 0.32 rad、
膝 0.45 rad、臂 0.22 rad），过大会看着像折腰。

## 手机上的手势

Godot 的「触摸模拟鼠标」在这套交互里是坑：`emulate_mouse_from_touch` 打开时，
单指会被当成鼠标左键（所以之前只能拖动），但**手机没有滚轮**，缩放就没了。
所以它被关掉了，触摸全部自己处理：

- 单指拖动 → 环绕（与桌面左键同一套阻尼，`yaw/pitch` 速度累加）
- 双指捏合 → 缩放：`k = 上一次两指间距 / 本次间距`，`k<1` 拉近；中心朝两指中点处的
  那个点挪（复用 `_point_under_cursor`）
- 双指一起拖 → 平移取景中心（按当前距离换算成世界位移）
- 缩放范围、地面兜底、8° 俯角下限对触摸同样生效

自检（合成触摸事件，不用真手）：

```powershell
godot --path v6 -- --touchtest
# TOUCHTEST 单指拖 yaw Δ=-1.708（应显著为负）  捏合 distance 111.51→55.76
# TOUCHTEST PASS
```
